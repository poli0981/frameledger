# Changelog

All notable changes to FrameLedger are documented here.

Format: [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).
Versioning: [Semantic Versioning](https://semver.org/spec/v2.0.0.html) — `MAJOR`
bumps for a database schema or IPC protocol break (`docs/11_UPDATER.md`).

`release.yml` reads the section for the tag being released (`tools/release-notes.ps1`) and
uses it as the GitHub release body. A missing or empty `## [x.y.z]` section is a **red
release**, not an empty note — so cutting a release means moving the `[Unreleased]` entries
under a `## [x.y.z] - date` heading in the same commit that bumps `VERSION`, then tagging
(`docs/13_CI_CD.md` §Branch & release policy). *(For a pre-release, `vX.Y.Z-beta.N`, `VERSION` already holds the
numeric core and does not move; the heading is the full version — corrected 2026-10-04.)*

### Changed

- **SonarCloud analyses the repository from CI** (developers only; owner decision D68). The owner turned SonarCloud's
  Automatic Analysis off and set the `SONAR_TOKEN` secret; `ci.yml`'s new `sonarcloud` job runs the SonarScanner for
  .NET 12.0.0 (a local tool, `.config/dotnet-tools.json`) after `check`, in a build of its own — the scanner turns
  warnings-as-errors off in the build it instruments, so it cannot wrap the gate's — with the gate's own test coverage
  (`build.ps1` now writes OpenCover beside Cobertura; the C# only, since the PowerShell tools and the native code have
  no coverage report) and CMake's compilation database for the C++, which
  `FrameLedger.Infrastructure.csproj` names to the scanner only in that build. `SonarQube.Analysis.xml` replaces
  `.sonarcloud.properties`. The job is advisory, not a required check, and waits for the quality gate, so a failed gate
  is a red job (`docs/13_CI_CD.md` §SonarCloud).
- **Dependabot, the NuGet audit and CodeQL** (developers only). Dependabot's version updates wait seven days after a
  release (security updates do not), and the actions' minor and patch releases come as one pull request a week. The
  NuGet audit is written down in `Directory.Build.props` (the whole graph, every severity — the SDK's defaults for
  net10.0), so a later SDK cannot move it. CodeQL also reads the workflows (`analyze (actions, none)`, not required),
  and a new push to a pull request replaces its CodeQL run.
- **The libraries Dependabot never updated.** Every NuGet pull request Dependabot opened here updated analyzers only,
  so the libraries fell behind with nothing to say so (`docs/13_CI_CD.md` §Dependabot and the NuGet audit). Updated by
  hand, each release at least seven days old (the cooldown Dependabot now keeps): the October .NET servicing release of
  `Microsoft.Extensions.Hosting`, `Microsoft.Data.Sqlite` and `System.Diagnostics.EventLog` (10.0.13) and `Dapper`
  2.1.89, which ship; for developers, the test SDK 18.11.0, `coverlet.collector` 10.1.0 and xunit 4.0.2. The licence
  texts under `legal/licenses/nuget/` name the new versions; no licence changed. Not taken: Markdig 1.5.0 (published
  the day before, and its licence is a reviewed copy at the packaged commit), Velopack 1.2.161 (the updater itself — a
  change to how updates install is the owner's to try), FluentAssertions 8 (its licence) and CsWin32 0.3.363 (with it
  the CI run's `NoSecondMatcherTests` could not read a generated constant — "Literal value was not found" — which a
  local run did not reproduce; it stays at 0.3.333 until that is understood).
