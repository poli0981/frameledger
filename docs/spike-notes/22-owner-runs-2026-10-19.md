## 22 · The owner's runs of beta.24 and beta.25 on real hardware *(2026-10-19)*

The owner ran the installed 0.1.0-beta.25 the evening it shipped and sent five screenshots: Silent Hill 2's session
summary and game page (21:33 local time) and Lies of P's summary (21:47). The numbers below are read from those and from a
read-only SQLite backup copy of the ledger (sessions 60 and 61) — never the data folder. Dev PC: i7-14700KF, RTX 5080,
NVIDIA driver 32.0.16.1742, 2560×1440 at 240 Hz.

### Silent Hill 2 — owner-only items 20(a) and 20(c)

Unreal Engine 5.1, Streamline 2.4.0. The NVIDIA App's profile for the game: DLSS override (preset L, Ultra
Performance); Frame Generation override (×6, preset B, *Dynamic*, target max refresh rate); Streamline DLSS override.

- **20(a), how frame generation was set:** *Set in the NVIDIA App: Dynamic, up to ×6, target: max refresh rate* — the
  App's own words. `NGX_DLSSG_DYNAMIC_MULTI_FRAME_COUNT_MAX` 5 read as "up to ×6" and the automatic target as "max
  refresh rate" stand on one title.
- **The mix** under Dynamic multi frame generation: ×2.0 17.70 % (111.83 → 225.83 FPS, 35 s), ×3.0 21.60 % (95.75 →
  287.18, 42.7 s, the steady state), ×6.1 7.59 % (23.20 → 140.53, 15 s), no frame generation 37.94 % (80.08 FPS, 75 s),
  not classified 10.12 % (20 s) — and **×1336.0, 5.06 %, 0.20 → 267.20 FPS, 10 s: a defect.** Its two windows held one
  application-frame token each against 1,336 presents each: a stretch the title presented through outside DLSS-G's frame
  count (the frame-time chart has a 14-second frame the same minute — a loading screen). A window needed eight presents
  and one token, so the ratio of one token was the presents themselves, and the steady state's own rule would have
  picked it had it lasted longest. The DLSS line then cited it: *DLSS 4.5 (a ×1336.0 frame-generation state)*. Fixed in
  beta.26 (`03_METRICS` §The mix): a window is read only with eight application frames and a ratio up to ×8
  (`FgWindow.GenerationCeiling`), a session or live ratio that held above it is refused as `beyond_generation`, and a
  stored mix is read by the same rule — this session's ten seconds join *not classified* and the DLSS line cites ×6.1.
  Of the 60 sessions in the ledger copy, this row was the only stored value above ×8.
- **20(c), what the override loads:** the summary's *Loaded* line lists `160_E658700.bin` 310.9.16.0 and
  `1B0_E658703.dll` 2.14.16.0 from the NVIDIA driver's NGX folder — no census name, which is why the DLSS line names no
  library. Which feature each serves is not established: 310.9.16 is a DLSS build number of the 4.5 generation, and
  2.14.16 reads as a Streamline version beside the profile's *Streamline DLSS override*.
- The driver line: *DLSS DLL chosen by the driver · preset L · Ultra Performance · Frame Generation override (×6)* —
  Ultra Performance from the report's 3, NGX's numbering (beta.24's correction, now on a second session). The header
  reads *Upscaler not identified · N/A*: the driver's super-resolution word has no `CREATED | EVALUATE`, as on
  2026-10-13, so no quality mode is claimed (D63's rule).

### Lies of P — owner-only item 21

Unreal Engine 4; `amd_fidelityfx_dx12.dll` 1.0.1.37507 (the SDK 1.1.x monolith) and `nvngx_dlss.dll` 3.7.0 loaded; FSR
chosen in the game's menu, its frame generation on.

- **The header reads *FSR 3 · 1707×961 → 2560×1440* — no mode.** The decision table's first branch. The query WAS
  hooked: `hooks_installed_mask` 0x83F carries `FL_HOOK_UPSCALER_QUALITY` (bit 11). 1707×961 is 2560×1440 at 66.67 %
  rounded up, not the vendor's answer to the size query (1706×960, truncated), so the title did not render at a size it
  asked for; at a ratio it asked for (1.5) it would have matched within the pixel the ratio path allows. So it either
  asked before the hook was in — a plugin's first query can follow the module's load on the loading thread before the
  watchdog installs — or never asked (its own table). Nothing recorded tells the two apart, and either way the honest
  answer is no mode: D65 stays built and silent for this title, as the table said. The Performance session was not run.
- Frame generation: ×2.0 for 87.93 % (54.64 → 109.62 FPS), not classified 12.07 % — FSR's own frame generation, named
  from its dispatches.
- The DLSS line: *DLSS 3 (library 3.7.0) · Super Resolution 3.7.0, from the game* — the engine's DLSS plugin loads the
  library while FSR upscales; D64 names DLSS 3 from its major version, and the line says the library is the evidence.
