### Owner-only item 20(a): the three ways frame generation is set

- **Chosen in the game's menu** (Cyberpunk 2077 — the owner: "cyberpunk 2077 là switch in-game"): ×2, ×3 and ×4 each
  formed a state with its own Native → Displayed, and the context line read *Set in the game*. The ×2 state was ten
  seconds at 186 → 353 FPS, read ×1.9; how long the owner held ×2 is theirs to compare.
- **The App's *Fixed ×6*** (Expedition 33): ×6.0, in the App's own words.
- **The App's *Dynamic*** (Silent Hill 2): ×2.0 and ×3.0 — and a ×2.52 row, below.
- **The Witcher 3 under *Fixed ×6* presented ×2.0 throughout.** The profile and the driver's report both say the
  frame-generation override applied (×6); the game presented one generated frame per application frame for the whole
  session, VSync on at 240 Hz. The rows are what the game presented and the context line is the setting
  (`03_METRICS` §The mix), so the summary shows both. Why the override did not reach this title — its frame generation
  is DLSS 3 through Streamline 2.14.1, and the driver loaded `1B0_E658700.dll` 2.14.16.0 beside it — is not
  established.

### A ×2.52 state — fixed in beta.27

Session 71's five-second windows, decoded from the copy with the App's own loader: ×2.00 for two minutes, ×3.00 for
three and a half, and where the *Dynamic* multiplier stepped, windows in between — at 135 s, 251 application frames
followed by one generated frame and 270 by two (×2.53), and ×2.62, ×2.70, ×2.31 later. Three of them pooled into a
×2.52 state for 12.8 s. Every shipping frame generation multiplies by a whole number, so a window is now a state's only
within 10 % of a whole multiplier (`FgWindow.IsNearWholeMultiplier`, `03_METRICS` §The mix); the stored row is read by
the same rule, and the session lists ×2.0, ×3.0, no frame generation and 7.36 % not classified. Of the 70 sessions in
the copy, it was the only stored row between two multipliers.

### The driver's word lost what it said while the game ran — fixed in beta.27

Expedition 33's header read *Upscaler not identified*, and no NVIDIA App mode, under an override the driver line
reports as applied (*preset L · Balanced*). Its stored super-resolution word is `0x8007F`; on 2026-09-06 the same game
under the same kind of override read `0x8067F` while it ran (§9) — the same word with `CREATED | EVALUATE`. The loop
asked the driver one last time after its last drain, after the game had closed, and that answer — the driver still
answers for the pid, with the two bits cleared — was the stored state. Of the 14 sessions in the copy in which the
driver answered, none kept the two bits; The Witcher 3's 2026-10-04 session (DLSS through Streamline, the game's own
library) stored `0x5` with its words marked *changed* between readings. So no stored session could read *DLSS
(driver-reported)*, and none on an NGX-direct title could name the override's mode (D63): owner-only item 20(b) could
not pass on any build before beta.27. Since beta.27 the driver is not asked once the game has gone, and the two bits
stand once a reading carried them (`NgxDriverState.Merge`).

### Start directly, and the crash safety

- **Lies of P hands itself to Steam** (2026-10-19, 21:43 and 21:46, *Start directly*): the process FrameLedger started
  left within five seconds with nothing presented, and Steam started the game 1 s later. That process was turned away
  while the first session was ending ("one at a time") and never recorded — a launch never said it had ended on its
  own, so nothing turned away during one was started after it. Fixed in beta.27 (`04_CAPTURE` §Watch).
- **Expedition 33 closes when started directly** (2026-10-20, 07:49–07:50, three starts): each process left within
  five seconds and read *crashed*, the third one refused and unhooked; no crash report and no Unreal crash folder for
  any of them. Through Steam the game ran.
- **The crash safety counted those exits.** Each was a hooked session's early abnormal end, and two turned hooking off:
  Lies of P at 21:46:36 on 2026-10-19 (the owner switched it on again within a minute; session 61 was measured),
  Expedition 33 after its second direct start (07:49:46; the third start was refused) and again at 07:51:06 — after a
  start outside FrameLedger that closed four seconds in with one frame presented, hooked: the only early exit of the
  morning that no direct start explains. The policy cannot tell a hand-off from the hang it exists for (`19_SAFETY`
  §Crash & stability safety); `LIMITATIONS.md` §Play tells users to start such a game through its store.

### The rest

- **Display sizes**: Lies of P's two sessions and three of Dark Souls III's stored no window or monitor size. A game
  leaving exclusive full-screen closes its window while its swap chain's last word is still fresh, and the tally kept
  the mode's last sample — exclusive, no window. Fixed in beta.27 (`03_METRICS` §Display mode).
- **The DLSS line read only *DLSS*** on The Witcher 3 under the override: the driver's copies loaded under names no
  census lists (`160_E658700.bin` 310.9.16.0, `1B0_E658700.dll` 2.14.16.0 — note `…700.dll` where Silent Hill 2 and
  Expedition 33 loaded `1B0_E658703.dll`). A line that would say only *DLSS* is not shown since beta.27; the *Loaded:*
  line prints the files.
- **Two summary windows of one session** (the owner's screenshot): opening a session whose window is open now brings
  that window forward.
- **Owner-only item 21** (FSR's mode on Lies of P): the *Performance* session read no mode either — the first branch on
  both. Its render size, 1280×720, is exactly the vendor's Performance size, so a query the hook met would have
  matched: the title did not ask while the hook was in. It cannot be launched by FrameLedger as the item asks.
