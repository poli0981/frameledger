## [0.1.0-beta.41] - 2026-11-12

**The forty-first pre-release: one fix, for Advanced metrics with the agent as administrator.** If you run the
capture agent as administrator with PawnIO installed and have **Advanced metrics** on, 0.1.0-beta.40 and
0.1.0-beta.39, which has the same code and where it was not looked for, could lose sensors: after most sessions the Advanced page stopped showing the processor's readings
until it was reopened, and now and then a whole session was stored with the graphics driver's seventeen readings
and none of the two hundred from the sensor library. The agent was closing the sensor library in one place while
another place was still reading it. It now opens and closes it in one place only, and never while something is
reading. If you do not use that combination, nothing changes for you. The same unsigned installer: verify its hash
against `SHA256SUMS.txt`, then *More info → Run anyway*.

**What it is not, yet.** The fix was made from the agent's log of ten real sessions; the fault needs an
administrator's agent with PawnIO to show, and has not been seen to be gone on such a PC yet. After a few sessions
the agent's log (Logs page) should no longer say *a device is left alone* or *the sensor library did not open*.
Everything 0.1.0-beta.40's notes say is not yet done still stands.

**Updating from `0.1.0-beta.40`:** Help ▸ Check for updates, then *Restart to update* with no game running. No
terms to read again, no change to the ledger (schema 23), the detection rules stay at `2026.11.2`. **The code
FrameLedger loads into a game — the overlay, the Vulkan layer, the shared-memory layout, the injector — is
0.1.0-beta.40's, line for line**; as after every update, a game that was running across it must be restarted
before it is measured again.

**A note on numbers.** The plan for Advanced metrics had named 0.1.0-beta.41 for its next step inside the game (two
new hooks). This fix took the number; that step is now 0.1.0-beta.42, and the ones after it move by one as well.

### Fixed

- **Advanced metrics: the processor's sensors no longer drop out after a session, and a session no longer loses its
  sensors at the start.** With the agent running as administrator and PawnIO installed, the sensor library was being
  closed by one part of the agent while another part was still reading it. After most sessions the Advanced page
  lost the processor's readings until it was reopened, and one session in ten stored only the graphics driver's
  seventeen series instead of two hundred and twelve. The agent now opens and closes the sensor library in one
  place, and does not close it while anything is still reading. Found in the first sessions recorded that way; the
  cause was read from the log and could not be reproduced without that setup, so the next sessions will show
  whether it is gone — the agent's log should no longer say *a device is left alone* or *the sensor library did not
  open*. Nothing changes in the code loaded into a game.
- **Two comparisons in the Advanced-metrics code say what they mean.** Whether a game gave FSR one field of view or
  a range of them was decided by comparing two decimal numbers for equality; it is now decided by comparing the two
  stored values bit for bit. Nothing you see changes. (Found by SonarCloud after 0.1.0-beta.40 was merged.)
