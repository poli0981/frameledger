## [0.1.0-beta.19] - 2026-10-12

**The nineteenth pre-release: an imported game that is its own runtime and not a helper, Change executable… in the game's
folder, the engine version of Unity, Godot and RPG Maker games, and games you uninstalled leaving the library by
themselves.** The same unsigned installer: verify its hash against `SHA256SUMS.txt`, then *More info → Run anyway*.

**Updating from `0.1.0-beta.18`:** Help ▸ Check for updates, then *Restart to update* with no game running. The Privacy
Policy (2.8) is shown once for you to accept. Every game is read once more for its engine (detection rules `2026.10.2`).
The agent removes the entries of games you uninstalled that have no sessions, about ten minutes after it sees them gone —
turn **Settings ▸ Data ▸ Remove uninstalled games** off first if you want them kept. An entry an earlier import made for a
helper is not changed: re-point it with *Change executable…*.

### Added

- **The engine version of Unity, Godot and RPG Maker games**, as Unreal Engine's has been shown since beta.10 — on the game's
  page with what it was read from, and the maker on the library card too: *Unity 2022.3.39f1* (from the player library,
  else its data file; a game whose data file is encrypted reads without the release letter, *2019.4.40*), *Godot 4.4.1*
  (from its data pack), *RPG Maker MZ 1.10.0* and *MV 1.6.2* (from the core script), *RPG Maker VX Ace (RGSS 3.0.1)*
  (from the runtime library its `Game.ini` names — that number is the library's, not the editor's). A Unity version used
  to read as its library's build number (`2022.3.39.5118735`), and a Godot one was never found. Every game is read once
  more after the update (detection rules `2026.10.2`). RPG Maker 2000/2003 is not recognised (`docs/05_DETECTION.md`
  §Engine version — Unity, Godot, RPG Maker).
- **The Privacy Policy (version 2.8)** names the files those versions are read from, and two that were already read and
  never named (Unity's player library and an RPG Maker game's title); it is shown once for you to accept.
- **A game you uninstalled leaves the library by itself** when it has no sessions: the agent removes an entry whose `.exe`
  has been gone for ten minutes, if its drive is connected and the folder it was installed in is still there — an
  unplugged or re-lettered drive never counts — and never one where anti-cheat was found. A game with sessions stays, with
  them, and reads *Not installed* as before. The Games page says so when it happens — once, naming them, for all the games
  one check removes; **Settings ▸ Data ▸ Remove uninstalled games** turns it off (`docs/02_SPEC.md` FR-1.8).

### Changed

- **Change executable… opens in the game's own folder** — the install folder a store made (`steamapps\common\<game>`
  and the like), or above an Unreal game's `Binaries\Win64`, else the folder the executable is in — instead of wherever
  the last file dialog was. For a game whose folder is gone it opens at the nearest folder still there
  (`docs/08_UI.md` §Games).

### Fixed

- **An imported game is no longer one of its helpers, and an RPG Maker MV/MZ game behind a launcher is its runtime.**
  A Doll's Locket - Remake (itch) was added as `notification_helper.exe`, NW.js's notification helper, because the itch
  app's own record named only that file (it leaves out a launcher that asks for administrator and anything a folder
  deeper) and the import took it as the game. A helper named by the store is skipped now and the executable is guessed —
  the import list says so — and the guess takes the executable beside NW.js's `nw.dll` and `package.json`, the process
  that draws (`css\Game.exe` there; its launcher asks for administrator, so it is measured with *Run the agent as
  administrator* on — *withdrawn 2026-10-13: that launcher is malware, do not run it; [0.1.0-beta.21]'s Security*). The
  import also no longer offers a store's game again when the library has it at another
  executable: an entry already there is re-pointed with *Change executable…* (`docs/05_DETECTION.md` §Library import).
- **The Games page shows its newest read of the library.** When two reads overlapped — a session ending while an import
  added games — the one that started first could finish last and be shown, an older list until the next read.
