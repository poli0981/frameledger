## [0.1.0-beta.29] - 2026-10-25

**The twenty-ninth pre-release: updated libraries, and SonarCloud analysing every change from CI.** The same unsigned
installer: verify its hash against `SHA256SUMS.txt`, then *More info → Run anyway*.

**Updating from `0.1.0-beta.28`:** Help ▸ Check for updates, then *Restart to update* with no game running. Nothing is
shown for you to accept again (the Disclaimer stays 2.11, the Privacy Policy 2.12), the ledger stays at schema 21, and
no game is read again: the detection rules (`2026.10.4`) are beta.28's. What you see and what is recorded are
beta.28's; the libraries under them are newer.

### Changed

- **SonarCloud analyses the repository from CI** (developers only; owner decision D68). The owner turned SonarCloud's
  Automatic Analysis off and set the `SONAR_TOKEN` secret; `ci.yml`'s new `sonarcloud` job runs the SonarScanner for
  .NET 12.0.0 (a local tool, `.config/dotnet-tools.json`) after `check`, in a build of its own — the scanner turns
  warnings-as-errors off in the build it instruments, so it cannot wrap the gate's — with the gate's own test coverage
  (`build.ps1` now writes OpenCover beside Cobertura; the C# only, since the PowerShell tools and the native code have
  no coverage report) and CMake's compilation database for the C++, which
  `FrameLedger.Infrastructure.csproj` names to the scanner only in that build. `SonarQube.Analysis.xml` replaces
  `.sonarcloud.properties`. The job is advisory, not a required check, and waits for the quality gate, so a failed gate
  is a red job (`docs/13_CI_CD.md` §SonarCloud).
- **Dependabot, the NuGet audit and CodeQL** (developers only). Dependabot's version updates wait seven days after a
  release (security updates do not), and the actions' minor and patch releases come as one pull request a week. The
  NuGet audit is written down in `Directory.Build.props` (the whole graph, every severity — the SDK's defaults for
  net10.0), so a later SDK cannot move it. CodeQL also reads the workflows (`analyze (actions, none)`, not required),
  and a new push to a pull request replaces its CodeQL run.
- **The libraries Dependabot never updated.** Every NuGet pull request Dependabot opened here updated analyzers only,
  so the libraries fell behind with nothing to say so (`docs/13_CI_CD.md` §Dependabot and the NuGet audit). Updated by
  hand, each release at least seven days old (the cooldown Dependabot now keeps): the October .NET servicing release of
  `Microsoft.Extensions.Hosting`, `Microsoft.Data.Sqlite` and `System.Diagnostics.EventLog` (10.0.13) and `Dapper`
  2.1.89, which ship; the CsWin32 source generator 0.3.363, which writes the Win32 declarations the shipped code calls;
  for developers, the test SDK 18.11.0 and xunit 4.0.2. The licence texts under `legal/licenses/nuget/` name the new
  versions; no licence changed. Not taken: Markdig 1.5.0 (published the day before, and its licence is a reviewed copy
  at the packaged commit), Velopack 1.2.161 (the updater itself — a change to how updates install is the owner's to
  try), FluentAssertions 8 (its licence) and `coverlet.collector` 10.1.0: the tracker it adds to each assembly it
  instruments declares a constant whose value reflection cannot read ("Literal value was not found"), and
  `NoSecondMatcherTests` reads every string constant in three of ours. The first CI run blamed CsWin32 for it; with
  coverage collected locally the failure followed coverlet, and 10.0.1 passes (`Directory.Packages.props` says so
  beside it).

### Fixed

- **The 34 C++ issues of `main`'s first SonarCloud analysis from CI** (developers only). Read with MSVC's real flags,
  the native code showed issues Automatic Analysis had not, on older lines; SonarCloud dates each by blame, and the
  two on lines changed since its new code began failed `main`'s gate on reliability. One was a defect in a test tool: `hook-harness --opengl` or `--vulkan` beside
  a D3D11 mode — or `--opengl` alone, which ran the default probes — called through a null swapchain; every mode that
  drives the D3D11 swapchain now asks first. The rest: `NvU32` printed with `%u` in `fl-probe-nvapi` (`%lu`; its
  machine line reads the same), a union and a `strlen` in the guard's tests, a `LARGE_INTEGER` read through
  `QuadPart` after `{}` had made its other member the active one (the Overlay's clock epoch, and the Vulkan layer's
  once-per-process enable-list read — now initialised through `QuadPart`), two terminators written after a read whose
  bound is now tested first, and five marked `// NOSONAR` with the reason above each. The Overlay compiles to the same
  instructions: built from either side, in one folder with one build id, its `.text` is byte-identical
  (`docs/13_CI_CD.md` §SonarCloud has the table).
