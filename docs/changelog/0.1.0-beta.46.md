## [0.1.0-beta.46] - 2026-11-13

**The forty-sixth pre-release: hooks go into a game together, and come out together.** Putting a hook in or taking
it out stops every thread of the game for a moment. Until now that happened once for every hook: in the first real
sessions on 0.1.0-beta.45 the thirteen NVIDIA Streamline hooks took between 0.7 and 2.8 seconds of a game's start,
and stopping a session took about a sixth of a second for each hook. The hooks FrameLedger finds something for at
one moment are now put in under **one** stop of the game's threads, and a stop takes all of them out under one.
This release is that change and nothing else in the part that runs inside a game; the pages are also brought up to
date with what those first sessions showed. The same unsigned installer: verify its hash against `SHA256SUMS.txt`,
then *More info → Run anyway*.

**What it is not, yet.** It has **not been run in a real game**. On FrameLedger's own test program nine hooks go
in within 78–90 thousandths of a second where they took 0.6–0.7 seconds, and eighteen come out within 76–90 where
they took 1.4–1.6 seconds; how long one stop of the threads is in a game with a few hundred of them, and whether
any game minds its hooks arriving together, are for the first real sessions to say. Nothing new is read and
nothing a hook reads has changed, so the terms are the ones you accepted. Of 0.1.0-beta.45's six new readings five
have now been read in real games; no game run so far set up a feature's resources after FrameLedger was in it, so
that row has not been seen. Everything 0.1.0-beta.45's notes say is not yet done still stands.

**Updating from `0.1.0-beta.45`:** Help ▸ Check for updates, then *Restart to update* with no game running. **The
terms are not shown again** (Privacy Policy 2.19 as before). No change to the ledger (schema 23), the detection
rules stay at `2026.11.2`. **The code loaded into a game changed in this release**, so a game that was running
during the update keeps the old part until it is started again.

### Changed

- **Hooks go into a game together, and come out together** (owner decision D134). Putting a hook in or taking it
  out stops every thread of the game for a moment, and until now that happened once for every hook: the thirteen
  Streamline hooks took 0.7 to 2.8 seconds of a game's start in real sessions (2026-11-13), and stopping a session
  took about a sixth of a second for each hook — two to three seconds, sometimes on the thread that draws. The
  hooks a moment finds are now put in under **one** stop of the threads, and a stop takes all of them out under
  one. On FrameLedger's own test program: nine hooks in 78–90 ms where they took 0.6–0.7 s; eighteen out in
  76–90 ms where they took 1.4–1.6 s. What a hook reads and when it is installed are unchanged, and no hook's own
  code changed. The log of the part inside the game has a new line for each such moment (`PATCH_BATCH`, with the
  time it took and the number of hooks). **Not run in a real game yet.**

- **The limitations, the accuracy statement and the user guide say what the first real sessions on 0.1.0-beta.45
  showed** (2026-11-13, six games): five of its six new readings were read in real games — every Streamline game
  asked whether its features are supported — and no game allocated a feature's resources after FrameLedger was in
  it, so that row has not been seen. No code changes.
