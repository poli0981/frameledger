**Choices made here:**

- **No C# 15 construct is used, although the owner asked for them.** The rule decided it, not a preference:
  ReSharper's engine, which Qodana runs, reads none of the four (`13_CI_CD` §C# 15 and the analyses, `spike-notes`
  §29). Unions would not have been the form in any case — the SDK's own CA1815 asks every union to hand-write its
  equality, and the shapes that wanted one are closed record hierarchies. What the release takes is API.
- **.NET 11's `IHost.RunAsync` is accepted, not wrapped**: a failed background service now ends the Agent through its
  crash report. A catch there would hide a fault, and could not reproduce .NET 10's exit exactly either.
- **A resting alpha says so in the build, not only in its notes**: the anti-cheat list reaches a user only inside a
  release, so an alpha nobody updates carries an ageing one. `FlAlphaLineRests` is stamped on both lines; the `alpha`
  branch sets it to false when it next tries a .NET.
- **"A prerelease .NET" is said only by a build that runs on one**, read from the runtime's own description — the next
  preview alpha says it again with no change to the code.
- **`release.yml` names the .NET 10 runtime `vpk` needs**, rather than relying on the hosted image carrying one.
- **The Community Qodana job was kept alive across the move** by installing the SDK into its container — an interim;
  the Ultimate linter replaces the job in the third part.
- **The 2026-10-31 forms stay where they read as well** (`json.AsSpan().TrimStart().StartsWith('[')` avoids a string):
  .NET 11's `char` overloads replaced a span only where the span was there for .NET 10's sake.

**Measured on the way** (`spike-notes` §28 and §29): the gate on SDK 11.0.100 — two analyzer sites beyond RC3's
twenty-one, both in tests written after the last alpha; `IHost.RunAsync` rethrowing, observed for the first time; the
first delta across two runtime majors (372 of 443 files patched, 72.6 MB on the rehearsal); `main`'s first full CodeQL

**Traps met on the way:**

- **A pull request's CodeQL C# run is an overlay analysis**: it extracts the changed files on top of `main`'s cached
  database, and its "scanned N out of N" is `main`'s baseline. #376 wrote "CodeQL reads `net11.0` whole" from one and
  was corrected, dated, two pull requests later with `main`'s own run. For anything the extractor has not met, dispatch
  `codeql.yml` on the branch (it takes `workflow_dispatch` since #380).
- **`ShmDrainIntegrationTests.TheGuardInjectsTheOverlayAndTheReaderDrainsRealFrames` failed once on the dev box** —
  "our own harness must not start matching the blocklist mid-run": the guard's re-scan refused the harness in one gate

- **A wiki page names no version** (`wiki-check`): "since 0.1.0-alpha.4" in `wiki/Releasing.md` was red. The guide's
  pages may.
- **The runner queue**: with three workflows per pull request and a probe's pull request open beside the train,
  `check` waited about 25 minutes for a runner. Cancel a probe's runs once it has told what it can.
- **A Bash heredoc halves the backslashes** of an inline Python regex — write the script with the Write tool.
- **`x.Should().NotBeNull(); x!.Member`**: ReSharper reads the `!` as redundant (Qodana's one finding on #376) and the
  compiler wants it. Keep the value the assertion needs, not the object.
- **CA2025** on a lambda that captures a `using` variable in a test: await inside a `try`, assert after.
- **A local gate reseeds `%LOCALAPPDATA%\FrameLedger\rules`** while the owner's installed copy runs beside it: the

### 0.1.0-alpha.4 — the fourth alpha, the same day, and the last for now (D98)

`alpha` takes main at this pull request — `v0.1.0-beta.37` and these notes, no other change — by a merge commit. **This
sync is not like the three before it**: main now holds what the switch held (`global.json`, the TFM, the three
packages, `legal/licenses/nuget/`, the *Transitive* row), so every switch file conflicts, and each is resolved by
taking main's — the branch's RC3 lines go, `RELEASE_LINE` stays `alpha`, and `git diff --name-only origin/main` on the
merged tree must print that one name. Its gate must pass on `alpha` before the pull request is merged by hand (the
branch has no auto-merge); the release runs from the signed tag `v0.1.0-alpha.4` on `alpha`, with its delta from
alpha.3. Its notes are `docs/changelog/0.1.0-alpha.4.md`: the warning, and that it is the last alpha for now.

  .NET has a preview. `FlAlphaLineRests` in `Directory.Build.props` says so to the build; the next trial sets it to
  `false` on `alpha` with the rest of the switch.
- **What a resting alpha costs its user** is in its notes, the guide and its banner: no update, the anti-cheat list
  included; and once ten betas have followed it, a copy of alpha.3 or older no longer finds alpha.4 (Velopack reads
  the newest ten releases).

**The sync and the release (2026-11-11).** #382 put the notes on main (`428b723`); #383 merged main into `alpha` by

### Qodana for .NET on the Ultimate licence — the managed report (D99, D100)

*Status is `docs/13_CI_CD.md` §Qodana and `CHANGELOG.md`; this is what no other file carries.* The third part of the
plan, in two pull requests: this one moves the existing job to Qodana for .NET (Rider's engine, native on a Windows
runner) and settles what it reports over the managed code; the next adds the C++ as a second report.

**Decisions:**

- **D99 — two reports from the start** ("Hai báo cáo ngay từ đầu"). The owner made a second Qodana Cloud project,
  `frameledger-cpp`, and the secret `QODANA_TOKEN_NATIVE`; the managed report goes to `frameledger` with
  `QODANA_TOKEN`. Both secrets are the owner's; no token was ever read or handled here.
- **D100 — where an inspection is switched off** (the plan's design, approved with it; it amends D93's "never in
  `qodana.yaml`"): in the place the engine that raised it reads — one of ReSharper's in `.editorconfig`; what has no
  key there in `qodana.yaml`. Hints are off as a severity. In code loaded into a game only defects are fixed.

**Choices made here:**

- **JetBrains' security rules stay on, scoped by path — which took four runs to find.** Every result was read first
  (the table in `13_CI_CD` §Qodana), and one place hardened (`ShellUrlOpener` refuses anything but `http`, `https`
  and `mailto`). Then the files read had to be told to the linter, and a rule's own id is honoured nowhere:
  `ignore`, an `exclude` path and `enabled: false` each left all 36 results standing. The report's own
  `log/effective.profile.xml` and `qodana_inspections_summary.csv` gave the answer — one inspection,
  `OpenGrepInspection`, produces every rule's results, and it does take a path. Between the third run and the
  fourth the rules were written as off, with a test in their place; the test stayed (`ProcessStartSitesTests`, in
  the gate, and wider than the rule), the rules came back on.
- **`PrimaryDisplay.cs` was not changed to please the linter.** Its six results come from an internal assertion in
  this linter's build (in the job's `backend.log`), not from the file; the first guess — that the engine misreads an
  `unsafe` tuple — was wrong, and a rewrite made on it was reverted. Two inspections are excluded for that one file,
  to be removed when a linter build reads it.
- **What the Ultimate licence offers and this job does not use**: quick-fixes (the job cannot push, on purpose), code
  coverage in Qodana, FlexInspect. If the licence lapses the job is red and advisory; the way back is in `qodana.yaml`.

**Traps:**

- **A security rule's id is not an inspection.** The OpenGrep plugin's rules all report through
  `OpenGrepInspection`; only that name works in `qodana.yaml`, and only by path. Read
  `log/qodana_inspections_summary.csv` in the report artifact to see which inspection produced a result before
  spending a run on a guess.
- **A report artifact is a zip inside the download, with backslash paths**: `unzip` extracts it and exits non-zero
  on the warnings, so do not chain on its exit code.
- **A linter result can be the linter's fault**: read the job's log directory (the report artifact carries it) for an
  `AssertionException` before changing the code it points at.
- **A Qodana run of the managed job takes fifteen to seventeen minutes**, most of it the scan; a pull request's own run
  reads the whole solution (`pr-mode: false`), so there is no quick partial run to iterate on.

**Then:** the native report, in the pull request after it — the next section.


### Qodana — the native report: the C++ through a solution CMake writes (D99, D100)

*Status is `docs/13_CI_CD.md` §Qodana and `CHANGELOG.md`; this is what no other file carries.* The second pull request
of the third part: the job `native`, `qodana-native.yaml`, the preset `x64-vs-analysis`, fifty-four `.editorconfig`
lines for the C++ and eleven small fixes outside code loaded into a game.

**Choices made here:**

- **One linter for both reports.** Qodana for .NET is the only linter of JetBrains' that reads this C++ (MSVC-only;
  `qodana-cpp` and `qodana-clang` are Linux images), and it wants a Visual Studio solution — so CMake writes one. The
  generated solution is never built from, beyond the one header a build generates.
- **No `.clang-tidy` file.** The plan had expected one. Every clang-tidy check and clang diagnostic the engine runs
  has an `.editorconfig` key of ReSharper's, so D100's "where the engine reads" is one file for all of the C++, and
  the repository gains no clang-tidy configuration that a developer's editor would start obeying.
- **Most of what it reported is not a fault, and the settings say why, line by line**: clang's opinion of code only
  MSVC builds; the engine misreading `atomic_ref`, zero-initialised API structures and constexpr tests; proposals of
  a newer idiom. Eleven things were fixed. **In code loaded into a game nothing was changed**: no defect was found
  there.
- **`LogNoteW` (`FrameLedger.Overlay/src/dllmain.cpp`) is dead code, and it is still there — the owner's call.**
  Nothing calls it. D100 changes code loaded into a game for a defect only, and an unused function is not one, so
  it was not removed on a linter's word; `.editorconfig` leaves that one file unread for an unused function, in a
  section that says to remove it with the function. Removing it is eleven lines with no caller: a pull request of
  its own, whose overhead statement is that the function was never reached.
- **"Possibly unused `#include`" is off, not obeyed.** Ten of the twelve reported outside the game are a file
  including what it uses (`<cstring>` for `std::memset`) although `<windows.h>` already brought it; removing them
  would have made the files depend on an accident.

**Traps:**

- **InspectCode cannot load the native solution on the owner's PC** (Visual Studio 18 Insiders' MSBuild crashes it,
  2026.2.3.1 and 2026.3.0 alike), so C++ results are read from CI: dispatch `qodana.yml` on the branch, download
  `qodana-report-native`, unzip the inner `qodana-report.zip`.
- **A file compiled into three targets is reported three times**: count distinct results (rule, file, line), not rows.
- **A shortened line is a clang-format change two lines away**: the gate's clang-format step failed on an alignment
  that the edit above it had made possible. Run clang-format on every native file touched before the gate.
- **Do not switch branches while a gate runs** — a probe branch was made during a local native build, which changed
  and restored two sources under it. Nothing came of it; the next gate was run on a still tree.
